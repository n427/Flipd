# Mobile Native Safety and Accessibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add branded native startup, contextual permissions, conversation reporting, Community Guidelines, and release-critical accessibility semantics.

**Architecture:** Keep permission policy in small pure helpers, leaving native API calls in `push.ts` and screens. Reuse the existing reporting endpoint and `ReportForm`; represent a conversation report by adding an optional `threadId` target validated server-side.

**Tech Stack:** Expo SDK 54, React Native, Expo Notifications/Image Picker/Splash Screen, Next.js API routes, Supabase, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-20-mobile-app-store-readiness-design.md`

## Global Constraints

- Do not request notification permission during session restoration.
- Permission denial must retain a usable fallback.
- Reporting copy must not promise live monitoring or response times.
- Reuse Flipd-owned branding and existing UI primitives.
- All behavior changes use red-green TDD.
